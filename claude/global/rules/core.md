# 작업 원칙 (전역)

## 완료·보고
- 검증한 것만 완료로 보고한다. 실행한 명령과 결과 요지를 함께 쓴다.
- 실행하지 않은 검증은 '미검증'으로 쓴다.
- 추측으로 빈칸을 채우지 않는다. 확인하지 못한 사실은 '미확인'으로 표기한다.
- 완료 보고 형식:
  - 변경 파일: `경로 — 변경 요지`
  - 검증: 실행한 명령과 결과 요지
  - 미검증: 실행하지 못한 검증과 이유
  - 범위 밖 발견: 사실만(수정하지 않음)

## 요청 범위
- 요청 범위만 수정한다. 임의로 확장하거나 축소하지 않는다.
- 범위 밖에서 발견한 문제는 고치지 말고 보고만 한다.
- 질문은 막혔을 때만 한다. 그 밖에는 가정을 명시하고 진행한다.

## 계획
- 복잡한 요청은 먼저 재진술한다: 목표 / 요구사항 / 유의사항 / 완료 조건.
- 여러 파일 수정이나 구조 변경은 플랜을 제시하고 승인받은 뒤 구현한다.

## 수정 전 확인
- 대상 파일 전체를 읽는다.
- 바꿀 함수·클래스를 import·참조하는 곳을 Grep으로 확인한다.

## 코드 작성
- 기존 컨벤션·포매터·린터 설정을 따른다.
- 설정을 완화하지 않는다: 규칙 끄기, line-length 늘리기, ignore 추가 금지.
- 훅·pre-commit 실패는 원인을 고친다. 우회하지 않는다.
- 변경은 작게, 단일 책임으로 나눈다.
- 주석·docstring 언어는 프로젝트 관례를 따른다. 관례가 없으면 한국어.

## 실행
- 테스트는 한 시점에 하나만 돌린다. 테스트 DB·포트·캐시를 공유하는 프로젝트가 많다.
- 긴 출력(로그·대량 결과)은 파일로 저장하고 필요한 부분만 읽는다.

## 메모리
- 메모리에는 저장소에서 알 수 없는 사실만 기록한다(사용자 선호, 환경 사실).
- 코드·문서·git 이력으로 확인할 수 있는 내용은 기록하지 않는다.
